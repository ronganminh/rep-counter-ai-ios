Lifecycle + sync
  • Workout saved → local: recompute enrollment progress, achievement progress, streak (pending). Server on sync: grants XP, completes challenges, unlocks badges (source of truth)
  • Client shows pending values with a "Counted on this phone" banner; celebrations only after server confirm (or local confirm when offline > 24 h, reconciled later)
  • All grants idempotent by source id; editing a set never changes XP; deleting a workout reverses its ledger entry and challenge progress
  • Challenge end: grace 72 h for unsynced sessions recorded before end (proposed)
Rules, tone + Free / Pro
  • Gamification never blocks or interrupts workouts; all core training is free
  • Free: all challenges, XP, levels, achievements, milestones and streak. Pro (Phase 8) may add custom challenges; no paid streak repair, no XP purchases, no loot
  • No leaderboards or social comparison in Phase 5
  • Copy: supportive, factual; "Behind pace" not "Failing"; ended challenges show progress, not failure
  • Levels unlock optional challenge types only
Localization + accessibility
  • Challenge and badge names are string keys; numbers formatted per locale (5:00, 1.000)
  • Badge names ≤ 18 chars EN to fit 3-column grid at 35% expansion (2 lines allowed)
  • Badges have text labels and state ("Locked, 10 of 14 days"); colour never sole signal (dashed outline + lock)
  • Celebrations respect Reduce Motion and are announced as a live region; all targets ≥ 48 pt except the 40 pt segmented controls already used in Phase 3
Existing vs proposed
  • Existing: XpIndicator (LV 4 · 395/500) on Home and Phase 3; October 500 card on Home; Phase 3 streak rule, markers and records
  • Proposed (Phase 5): challenge catalog and enrollment, XP ledger rules, level thresholds, achievements, milestones timeline, celebration rules
  • Open: final XP values, max active challenges, grace window, whether repeatable badges show counts
