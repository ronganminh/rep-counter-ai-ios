Offline save behaviour
  • Every workout is written to local storage before any network call; the outbox uploads with clientSessionId (UUID) so retries and double taps can't create duplicates (server upsert, 409 = already have it)
  • Auth expiry or sign-out doesn't block saving; queued items keep their owner and upload after the same account signs in (Phase 9 merge rules)
  • Background: iOS beginBackgroundTask for the local write; uploads via WorkManager / BGTaskScheduler (proposed)
  • AI feedback is requested only after the server stores the session; AI failures never roll back the save
Delete / undo rules
  • Single workout: tombstone + 5 s undo (v1 undoWindow), then local delete; server DELETE by sessionId (idempotent); other devices apply tombstones on sync; tombstone beats older edits
  • Clear history: typed confirmation (DELETE / XÓA, also XOA); no undo; export offered first; phone / account / both are separate operations; partial failure keeps local tombstones
  • Adopted design policy (A-04, proposed pending backend review): deleting a workout removes it from history and metrics (totals, records, streak, charts, October 500) but does not revoke XP or achievements already earned. Verified competition results stay server-authoritative; fraudulent / duplicate / invalidated workouts may get server-side reward correction; whole-account deletion follows account-deletion + retention policy. Milestones are never silently erased
  • Account deletion stays in Phase 9 (P9-11d / e); Final A never deletes accounts
AI consent + credits
  • Post-workout feedback is free (Phase 8). Retry reuses requestId; failures release holds; nothing is charged twice
  • Consent deferred → card offers review once per workout; never blocks results
  • Deeper analysis uses requests; at 0 shows allowance info (P8-05c); Pro-only analysis shows a quiet lock (P8-04c)
  • Payload is workout numbers only (v1 §8.3); share images never include AI conversation text
Privacy + data
  • Share: username off by default; no camera image, face, location, email or AI chat; source label (camera / timed / by hand) always shown
  • Support: diagnostics opt-in and itemised; no tokens, passwords or video; screenshots exclude camera view
  • Delete / clear: explains phone vs account scope in plain words; export link before irreversible actions
  • Startup: no analytics before consent (Phase 9)
Accessibility
  • Hold to finish: VoiceOver / TalkBack custom action "Finish workout" with a confirm instead of a timed hold (accessible alternative)
  • Swipe delete has a visible ··· button and a screen-reader action
  • Status changes use aria-live / SemanticsService.announce; undo toast persists while focused
  • Targets ≥ 44 pt (most 48–56); no text in the HUD body zone; dialogs trap focus, default focus on the safe action
  • Reduced motion: splash ring and hold ring become static progress text
  • Dynamic Type: result hero scales down to 64 pt minimum; rows wrap to 2 lines
