Session + timer lifecycle
  • States: active ⇄ paused, active → resting → active, → completed | ended_early. Each transition is written locally before the UI updates
  • Workout clock = sum of active segments (monotonic clock); paused time excluded
  • Rest: deadlineAt = now + duration; UI derives remaining. +15 s → deadlineAt += 15 s (or now + 15 s if expired). Skip clears rest. Pause stores pausedRemainingMs
  • Background / lock: camera released, active set auto-pauses. During rest a local notification is scheduled at deadlineAt and rescheduled/cancelled on +15 s / Skip. No claim of uninterrupted background execution
  • Return: recompute from deadlineAt; expired → "Rest ended Xs ago". Killed app → relaunch reads the session → P2-07c
  • Speech cues are system TTS output. Microphone is never requested
Local persistence + sync
  • Plan, templates and exercise catalog cached; today's workout runs offline
  • Session + SetActual written locally first; upload PUT /sessions/{id} (idempotent, client UUID)
  • Visible sync states: Train pending chip, completion banner, Retry. Auto-retry on reconnect (proposed)
  • Plan edits and rescheduling need network (server conflict check with version). Offline → disabled with reason
  • Version conflict → refetch and reopen the sheet with updated options
Localization
