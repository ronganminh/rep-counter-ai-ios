Data integrity rules (B-05)
  • Every total in the prototype is computed from one session list: workouts, reps, held, time, streak, October 500, XP, records, race.
  • Each workout has a clientId at creation; saving, retrying sync, recovering a draft and merging guest data never add a second record.
  • Deleting history recalculates totals / records / streak but keeps XP, achievements and server-authoritative challenge progress (A-04).
  • Manual reps count toward history but not toward camera challenges or races.
DIntegrated prototypePart 12 · what is real, what is simulated
Real
  • Inside the integrated prototype: all 39 screens share one state; every button changes that state
  • Links out (detailed design per screen, Delete my account → P9-11e, Export → P9-11b) open other canvas files — real links
  • Phase 3–8 Profile tabs, Home bell / pill, Phase 9 deletion + help rows → real links between files
Simulated
  • Camera counting (demo buttons: +1, +12, count to 35)
  • OS camera and notification prompts
  • Push notifications (banner) and deep-link delivery
  • Store sheets (StoreKit / Play Billing / Lemon Squeezy web), receipt verification, Ask to Buy, restore
  • Rewarded ad (Android only)
  • Server sync, merge dry-run, AI responses, support ticket
  • Network on / off · 1-second hold timer is real
Limitations
  • Separate canvas files cannot share live state. Opening a Phase file shows that file's own sample state, not the prototype's.
  • EN / VI switching covers every prototype screen; Phase files keep their own EN / VI tables. v1 Vietnamese screens are unchanged.
  • The prototype is one phone at 393 × 852; Android-specific chrome (system Back) is described in FA-10 rather than simulated.
  • Phase files were not refactored to the unified component set (mapping only, section E).
