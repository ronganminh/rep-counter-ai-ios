Speech queue lifecycle
  • Every utterance carries {sessionId, setId, priority, dedupeKey, createdAt, ttlMs}
  • enqueue: drop if dedupeKey seen; if priority 1 → stop() current + clear lower; if same key family (rep count) → replace pending
  • dequeue: discard if now − createdAt > ttl (rep 1.2 s, form 1.5 s, rest 3 s) or setId ≠ current set → no stale announcements after a set/exercise change
  • merge: count + near/halfway/set-complete in the same 300 ms window → one utterance
  • one utterance in flight; awaitSpeakCompletion(true); next starts on completion
  • mute: stop() + clear; captions still emitted from the same queue

  Stream<SpeechCue> get cues;      // captions + log

abstract class TtsEngine {          // flutter_tts adapter (verify)
  Future<bool> init();

  Future<bool> isLanguageAvailable(String locale);

  Future<void> activate({bool duckOthers});
  Stream<AudioInterruption> get interruptions;
  Stream<AudioRoute> get routes; }

Lifecycle + offline
  • Foreground → resume: re-query voices, re-apply settings, speak nothing until next event
  • Background / lock: stop() + clear queue; rest uses one local notification at restEndsAt (Phase 2 deadline model)
  • Route change (headphones removed): stop current utterance; iOS pauses nothing else; show pill "No audio" only if no output
  • Offline: on-device engine only; network-only voices hidden; history and settings local
  • Latency target: REP_ACCEPTED → speak() call < 100 ms on device (proposed); no network on the hot path
Privacy + safety
  • No microphone permission, no speech recognition, no recording in Phase 6
  • No video or audio uploaded. Coaching history is text on device (optional, 30 days)
  • AI (Phase 4) text never spoken verbatim during sets; only approved templates with slots; requires Phase 4 consent
  • Form cues only when the shipped rule fires; same wording as the on-screen chip; no medical or injury language
  • Mute is one tap; all safety controls (Pause, Hold to end) work without audio
Localization
  • String keys with ICU plurals for all templates (EN + VI). Numbers spoken by the engine in locale
  • VI samples from v1: "Tám", "Còn 4", "Giữ thân thẳng", "Chậm lại", "Nghỉ chín mươi giây", "Còn mười giây"
  • Captions wrap to 2 lines; HUD pill text ellipsizes
  • Coach locale may differ from UI locale (open decision)
Existing vs proposed
  • Existing (v1 design): spoken rep numbers + 3-2-1 via flutter_tts vi-VN; "Read numbers aloud", "Vibrate each rep", "Sounds" switches; pill shows spoken text; voice confirms save
  • Proposed (Phase 6): event queue with priorities, rest/next/form/encouragement speech, voice + language picker, speed/volume, audio modes, captions, coaching styles, history, error recovery
  • Not verified: flutter_tts presence and behaviour in the codebase; voice lists per device; ducking on each OEM
Open decisions
  • Respect iOS silent switch or override (playback category)?
  • Background rest speech (iOS audio mode / Android foreground service) — out of scope now
