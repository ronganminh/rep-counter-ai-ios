  • Access token: memory only; short-lived (≈ 15 min, proposed); refresh token rotated on each use, reuse detection revokes the family

  • Workout data: local DB (e.g. Drift/SQLite) per account namespace + a guest namespace; wiped namespaces only on explicit delete

Guest migration + sync rules
  • Client ids: every workout / set gets a UUIDv4 at creation on device (guest or signed in); the server never re-ids
  • Idempotent upserts: /sync/batch keyed by clientId; retries return the stored result — nothing counts twice (XP, streaks, challenges, leaderboards derive from server records)
  • Versions: version counter + updatedAt per record; mismatch → conflict, never silent last-write-wins for user-edited values
  • Queue: persistent FIFO outbox; exponential backoff with jitter; survives app restarts; per-item status
  • Guest → account: dry-run first (P9-06b shows matched / new / conflicts); user confirms; upload; conflicts reviewed (P9-06d). Rollback = guest namespace is kept until the server confirms every item
  • Account switch: local data is namespaced per account; signing into a different account never merges silently — prompt first (P9-05g)
  • Duplicates: same exercise signature + start within 2 min + device → P9-12g suggestion; user decides
Account deletion
  • Three scopes, three actions: local history (device only) · cloud workouts · entire account (P9-11d)
  • Reauth → typed confirmation → 202 Accepted; tokens revoked on all devices; client switches to guest
  • Status: requested → processing → completed (email). Timelines, backups and grace period come from the Privacy Policy — not promised in UI
  • Store subscriptions are NOT cancelled automatically; screen links to manage subscription (Phase 8)
  • Required: in-app account deletion (App Store Review Guideline 5.1.1(v)); Google Play account deletion requirement incl. a web deletion link — verify current text before release
