| L-D16 | D-16 database package and migration | **sqflite** (not drift). Workouts move to SQLite (`repcoach.db`: `workouts(id, client_id, started_at, raw)`, `unreadable_workouts`, `meta`). The record JSON is stored verbatim so unknown/future fields survive. Import from `workout_history_v1` runs automatically on every open with `INSERT OR IGNORE` by workout id, then verifies every readable legacy id is present (idempotent, no duplicates, no loss); unreadable legacy entries are kept byte for byte. The SharedPreferences list is **kept as the rollback copy** (never deleted by the migration); if the database cannot be opened or verification fails, the store keeps working on that list exactly as before. Deletes and "clear history" also remove the record from the copy, so deleted data cannot come back. 100-record cap removed; every record gets a stable UUID `client_id` (for A-2 merge) | sqflite runs queries off the UI thread on device and needs no code generation (`build_runner`) or schema DSL; the store is small and key-based, so drift's typed queries add little. Tests use `sqflite_common_ffi` (no-isolate, in-memory) so the existing widget tests run unchanged | Switch the store back to the legacy list (fallback code is still there), or replace the database layer with drift behind the same `WorkoutHistoryStore` API | Mobile tech lead |
| L-D17 | F-4 drafts and D-06 window | Drafts are recorded **from `WorkoutUiState` only** by a listener created in `CameraPage` (no change to `WorkoutController`, `RepCounter`/`RepTracker` or the HUD). A draft is written only when the counted reps or sets change and cleared when the workout is saved or discarded; it is off during the CI video replay. Recovery window = **12 h** (D-06 PROPOSED value), a constant. Expired drafts are still offered as Save partial / Discard, never discarded silently. "Save as partial" writes one record with a fixed id (`draft-<start>`, `partial: true`, no form data); a draft whose workout was already saved is cleared instead of offered. **Resume (continue the same count) is not implemented**: it needs the engine to start from a saved count, which the owner ruled out of scope | Owner: engine and HUD untouched; D-06 still PROPOSED | Change `WorkoutDraft.recoveryWindow`; Resume needs an engine-owner change to seed `WorkoutController` | Product + Mobile (Resume: engine owner) |
| L-D18 | W-4 manual tracking | Manual entry is a separate screen (per-set − / + steppers, add/remove set, Save) opened from the camera gate ("Track manually"), so the camera flow and engine are untouched. Records carry `source: "manual"` (absent for camera records, so old records read as camera), mode `free`, no form data, and are labelled "Manual" in history. Per D-18 they are excluded from timed personal bests and challenges. The **guided timer** half of W-4 is deferred: it has no approved copy for its states in the ARB and would need new strings | D-18 CONFIRMED (design); ARB must stay unchanged | Drop the `source` field and the screen; add the guided timer once its copy exists | Product |
